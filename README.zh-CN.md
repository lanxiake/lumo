# Lumo

一个开源的 **儿童 AI 虚拟伙伴** —— 一个会聊天、会教学、会陪玩的屏幕角色。
Lumo 通过自然对话，帮孩子探索 **无代码编程、音乐、数据、语言、游戏和绘画**。

- **自带模型（BYO）** —— 在 App 内配置任意兼容 OpenAI 或 Anthropic 协议的服务商。
  你的 API Key **只保存在设备本机**，直连你配置的服务商。没有 Lumo 后端、没有中转
  服务器、无需账号。
- **独立运行** —— AI Agent 跑在设备内嵌的 Node.js 运行时（`nodejs-mobile`）里。
  无需登录、无需注册、不依赖云端。
- **内置语音** —— 设备端语音识别（sherpa-onnx）+ 在线语音合成（TTS）。
- **Android & iOS** —— 基于 React Native 构建。

> Lumo 脱胎于一个内部项目，被重构为一个专注、自包含的学习伙伴。"宠物"角色只是它的
> 外表 —— 内核是一位能干的老师和玩伴。

## 工作原理

```
┌─────────────────────────────┐
│  React Native App（界面）    │
│  ├─ Live2D 角色              │
│  ├─ 语音（设备端 ASR）        │
│  └─ 设置：模型提供商           │
└──────────────┬──────────────┘
               │  RN ⇄ Node 桥接
┌──────────────┴──────────────┐
│  内嵌 Node.js 运行时          │
│  └─ AI Agent  ──────────────►│  你的 OpenAI / Anthropic 端点
└─────────────────────────────┘
```

App 内置的 AI Agent **运行在设备内部**。当你在设置里配置了模型提供商，Agent 会用你的
Key 直接流式访问该端点。全程不经过任何 Lumo 服务器。

## 设计思想

Lumo 建立在一个信念之上：低龄孩子学得最好的方式，是**和一个他喜欢的角色说话**，而不是
在菜单里点来点去。下面的一切都服务于这个目标。

- **语音优先，双手可选。** 3–8 岁的孩子未必识字流畅。核心循环是*听 → 理解 → 说 → 反应*，
  孩子不碰屏幕也能进行真正的对话。
- **设备即运行时。** Agent 活在 App 内部，而非某个你必须信任的云服务里。你的 API Key
  和对话都留在手机上，**直连**你选择的模型提供商。
- **角色是界面，不是装饰。** 情绪、动作、口型由对话状态驱动，孩子能像面对真人一样读到
  *情绪*与*轮流说话*的节奏。
- **安全靠代码强制，不靠提示词。** 儿童安全的提示词包装、敏感工具（如画画）的硬确认门控
  都落在工具层，聪明的模型或好奇的孩子都绕不过去。

## 关键技术

这一节是诚实的、代码级的巡览。凡是刻意做了简化的子系统（例如用文本级回声抑制替代音频
AEC），都会明说。

### 设备端语音识别（ASR）

语音识别**完全在设备上运行** —— 用于转写的音频永远不离开手机。

- **引擎：** [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) **流式 zipformer**，
  中英文**双语**，int8 量化以适配移动端，配合 **Silero VAD** 做人声活动检测。
- **流式而非批处理：** 孩子说话的同时就吐出中间假设，让打断和界面反馈能在话说到一半时
  就响应。
- **串行化生命周期：** 单一原生识别器（`NativeModules.SherpaAsr`）通过单例串行化
  `start`/`stop`，避免并发会话频繁开合导致的原生崩溃。
- **VAD 与 ASR 文本是两路独立信号**，静音检测与断句不依赖解码器输出。

### 语音打断（角色说话时插话）

孩子就是会插话。Lumo 把这当成一个特性，用**两段式"预备—触发"**门控：一声咳嗽不会打断
角色，但真正的"等一下，停！"可以。

- **预备（Arm）：** TTS 播放期间，孩子的实时转写要同时达到
  `BARGE_IN_MIN_CHARS_WHILE_SPEAKING`（3 个字符）**且**越过麦克风能量下限
  （`BARGE_IN_MIN_MIC_LEVEL` = 0.04），才进入预备。
- **触发（Fire）：** 该意图要持续 `BARGE_IN_CONFIRM_MS`（250 ms）角色才真正停下 ——
  借此排除瞬时杂音。
- **冷却：** 打断后 `INTERRUPT_COOLDOWN_MS`（700 ms）内不再重复触发。

### 回声与"自听"抑制

角色用的扬声器，麦克风也听得到。Lumo 没有上重量级的音频 **AEC（声学回声消除）** DSP，
而是用更轻、也更契合"轮流说话"场景的**文本级**策略：

- **半双工偏置** —— 流水线避免对"疑似角色听到自己"的输入作出反应。
- **文本级回声检测**（`echoTextFilter`）—— 用多种相似度度量把新转写和角色刚说过的话
  作比较：子串与折叠形式匹配、二元组 **Jaccard** 相似度、覆盖率、子序列与 **LCS** 检查、
  以及重复折叠比。若一段转写看起来是 TTS 输出回灌进来，就丢弃。
- `ponytail:` 这**不是**真正的音频 AEC。取舍：几乎零 CPU、无原生 DSP 依赖，代价是无法
  处理真正的同时双讲。若产品需要，全双工 AEC 是后续升级路径。

### 噪音与垃圾过滤

嘈杂操场上的流式 ASR 会产出垃圾。转写在抵达 Agent 之前先过一条 **7 级级联**
（`asrGarbageFilter`），并刻意偏向漏报（放真话通过）而非误杀（绝不吃掉孩子真正说的话）：

1. 短但有效的白名单，2. 单一语气词拒绝，3. 垃圾短语黑名单，4. 重复字符刷屏（≥85% 同一字），
5. 纯语气词，6. 汉字占比过低（<0.3），7. 叠加语气词正则。

### 口型同步

嘴部动作是**确定性、时间驱动**的，而非音素或音频驱动 —— 这让它在 TTS 播放时既顺滑又便宜。

- `computeMouthOpen(t)` 叠加一个 **3.5 Hz** 主正弦与一个 **7.0 Hz** 次正弦（×0.4），
  半波整流并归一化后加一点增益。
- `smoothMouthValue` 走 **EMA**（α = 0.5），让下巴在帧间平滑过渡而非跳变。
- `ponytail:` 刻意不做音素级精确。对孩子而言它"看着像在说话"就够了，且几乎零成本；真正的
  音素驱动口型是后续升级项。

### 动作、表情与情绪

角色的肢体语言，就是对话状态的直接读出。

- **状态 → 表情策略：** `expressionForState` 把 Agent 的九种运行状态（待机、聆听、思考、
  说话……）映射成 `{ emotion, motionGroup }`。渲染器（`PetCoreRenderer`）把情绪名解析为
  模型特定的表情索引，并播放对应的 Live2D 动作组。
- **来自模型的情绪标签：** LLM 可以内联输出 `[joy]` / `[curious]` 这类标签。
  `emotion-tag-parser` 把它们提取出来（`\[([a-zA-Z0-9_一-龥]+)\]`）驱动表情，然后在
  **TTS 之前剥离**，孩子永远不会听到标签被念出来。

### 记忆

记忆是**设备本地**的。移动端运行时把会话与短期记忆持久化到设备本机的 **SQLite** 库
（Node 侧用 `node:sqlite`，RN 侧用 `op-sqlite`），经 `local-session-memory`：

- **四张表：** `sessions`、`messages`、`local_memories`（按 pet 的 `key → value`）、
  `tool_audits`。
- **可审计、可擦除：** 每次敏感工具调用都记为一条简短、脱敏的摘要（绝不记完整输入、JWT
  或 API Key），并提供一等的删除路径（`deleteSession`、`clearMessages`、`clearMemories`）。
- `@lumo/agent-runtime` 还内置了更完整的记忆架构（规则/LLM 提取、带权重注入的分类记忆），
  伴侣可以据此逐步成长。

### 动态应用与游戏

Agent 能**即时生成互动内容** —— 一个小游戏、一张图表、一个数学可视化、一块画布 —— 并在
App 内渲染。

- **A2UI 组件：** 一套精选组件（Chart、MathVisualizer、Text、Card、Image、Button、List、
  音/视频播放器、DataTable……），由模型组合成实时视图。
- **Artifact 沙箱：** 模型自由编写的 `html` / `svg` / `javascript`，渲染在**沙箱化
  WebView**（`PlaygroundView`）里 —— `originWhitelist` 锁死为 `about:`，通过
  `window.sendToPet` 消息桥回传给角色，带崩溃恢复（`onRenderProcessGone` /
  `onContentProcessDidTerminate`）与 5 分钟自动关闭以约束内存。

### 绘画

孩子可以让角色画画。`image_generate` 会给每个请求包上**儿童安全提示词前缀**（温暖、可爱，
无文字/暴力/成人主题/隐私信息），并挂在**工具层硬确认**（`requestConfirm("drawing", …)`）
之后，模型无法跳过。

- 生成的图片以内存中的 **data URI** 返回，经 `image_ready` 事件显示在画廊里 —— Lumo
  **不会**把图片文件写入设备文件系统，从而避免跨平台路径问题、缩小隐私面。
- 注意：与聊天（直连你配置的提供商流式）不同，画图目前是**向一个图像生成服务端点发起
  POST**。请把它指向你自己的提供商/网关；它不是在设备端完成的。

## 快速开始

需要 Node.js >= 18 和 [pnpm](https://pnpm.io) 9。

```bash
pnpm install

# 下载设备端语音识别模型
pnpm setup:sherpa

# 运行
pnpm android    # Android
pnpm ios        # iOS（需 macOS + Xcode）
```

然后在 App 内打开 **设置 → 模型提供商**，填写服务商信息（协议、Base URL、API Key、
模型名），即可开始对话。

### 可选：联网搜索

Lumo 可接入自托管的 [SearXNG](https://docs.searxng.org/) 实现 `web_search` /
`web_fetch`。设置 `SEARXNG_BASE_URL`（见 `.env.example`）。留空则禁用联网搜索。

## 技术路线图

> 以下为 **规划方向**，尚未实现，用于说明 Lumo 作为学习伙伴的演进目标。

### 1. 课本知识图谱与个性化学习

将国内小学、初中、高中、大学的课本知识，构建为结构化的**知识图谱**，并据此为每个孩子
规划学习路径。

- **知识图谱** —— 把各学科的知识点建模为节点，标注明确的**前后依赖关系**（哪些知识
  是另一些知识的前置），并对齐年级与课本章节。
- **儿童知识评测** —— 以轻量、对话式的方式评估孩子对各知识点的掌握程度，形成每位学习者
  的掌握度图谱。
- **定制学习计划** —— 沿知识图谱的依赖关系，从孩子"已掌握"的知识出发走向新目标，生成
  顺序正确、因人而异的学习计划，在恰当的时机推送恰当的下一个知识点。

### 2. 稳定、成熟的动态内容渲染

强化 Agent 生成的动态互动内容（A2UI 组件、HTML/SVG/JS 沙箱产物、小游戏）在设备端的
渲染与编排方式。

- **更稳健的渲染流水线** —— 成熟、经充分测试的渲染/编排路径，减少边界场景 BUG，生命周期
  处理可预期。
- **更低内存占用** —— 更精细的 WebView / 资源生命周期管理，降低移动设备上的内存压力与
  进程被回收的概率。
- **更高成品品质** —— 跨设备行为一致，交付更精致、可靠的成品应用体验。

### 3. 彻底设备端、离线优先

把"设备即运行时"的故事讲到底 —— 让伙伴在飞机上、在信号不好的乡村也能用，也让孩子的
数据更彻底地留在本地。

- **离线语音合成** —— 提供设备端 TTS 语音作为当前在线合成的替代，让整条对话循环在完全
  无网时也能跑。
- **可选的设备端小模型** —— 内置一个本地小 LLM 用于基础聊天与离线兜底，同时仍允许高级
  用户指向更强的云端模型。
- **直连提供商生图** —— 让画图走和聊天一样的路径（直连你配置的提供商），去掉当前对独立
  图像生成服务端点的依赖。

### 4. 语音流水线成熟度

把音频链路从"够用来轮流说话"提升到"自然的全双工对话"。

- **真正的声学回声消除（AEC）** —— 真正的全双工音频路径，让孩子可以*盖过*角色说话，
  替代当前较轻的文本级回声抑制。
- **音素级精确口型** —— 用真实的 TTS 音素/口型流驱动嘴部，而非确定性波形，让发音可信。
- **唤醒词与说话人感知** —— 常听唤醒 + 基础说话人区分（孩子 vs 大人），让免手操作更安全
  自然。
- **方言与口音鲁棒性** —— 拓宽 ASR 对地方口音和低龄儿童发音模式的覆盖。

### 5. 多模态感知

让孩子能*给你看*，而不只是*说给你听*。

- **视觉输入** —— 把摄像头对准作业、一幅画或现实中的物体来讨论，配以儿童安全的视觉流水线，
  以及和别处一致的硬确认门控。

### 6. 更深的记忆与个性化

从本地短期记忆，成长为一个真正记得住、会适应的伙伴。

- **设备端语义召回** —— 把 `@lumo/agent-runtime` 里已有的更完整记忆架构（规则/LLM 提取、
  带权重的分类注入、向量"记忆宫殿"召回）接到设备本地运行。
- **长期情景记忆** —— 跨周、跨月地记住孩子的兴趣与里程碑，反哺路线图第 1 项的知识图谱
  掌握度地图。

### 7. 家长体验与安全

让 Lumo 成为家长能放心交到孩子手里的东西。

- **家长仪表盘** —— 屏幕时长限制、对话回顾、内容/话题管控，背后由可审计的本地工具调用
  日志支撑。
- **成长报告** —— 基于评测与知识图谱数据生成人类可读的学习总结，让家长看到孩子在探索
  和掌握什么。

### 8. 角色与内容生态

把角色及其能力向社区开放。

- **自定义角色与语音包** —— 换入更多 Live2D 模型与语音，让家庭挑到孩子喜欢的伙伴。
- **技能与内容扩展** —— 一套干净的扩展模型，用于新增学习活动、小游戏和学科包。

## 隐私

Lumo 为儿童设计。它**不收集任何数据**，也没有后端。除了直连你配置的模型提供商这一次
调用之外，对话内容不会离开设备。详情见各包内说明。
